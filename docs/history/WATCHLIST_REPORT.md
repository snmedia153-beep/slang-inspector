# 첨부 키워드 목록·ㅇㄹ 원형 후보 반영 결과

작성일: 2026-10-29

## 1. 원인

기존 사전·초성 대조만으로는 첨부 관리 표의 모든 항목을 문장 안에서 대조할 수 없었습니다. 표에는 일반어·숫자·지역명·정체성 표현도 있어 전체를 성적 은어로 등록하면 오탐이 발생합니다. 관리 버튼의 `비활성`을 행 상태로 읽거나, 검색어 수집 용례를 해당 표현의 뜻을 검증한 자료로 취급해서도 안 됩니다.

실제 로컬 모델 검사에서는 `ㅇㄹ 레시피`에도 성적 풀이를 우선하는 편향이 확인됐습니다. 후보 원형을 늘리는 것과 일상 문맥을 비교하는 처리가 함께 필요했습니다.

## 2. 수정 내용

- 첨부 표 **200개**를 원문 표기·타입·행 상태와 함께 등록했습니다. 은어 126·일반 35·유인문구 39개이며 행 상태는 모두 활성입니다. 관리 버튼·등록 시각은 분석용 키워드에서 제외했습니다.
- 기존 DB 사전과 별도로 문맥 목록을 대조합니다. 동일 위치의 기존 사전 분류를 우선 보존하고, 가능한 원형을 합칩니다. 이 목록 개수를 기존 수집 사전 개수에 더해 중복 집계하지 않습니다.
- 띄어쓰기·기호·조사와 `몸사판매` 같은 등록어의 연속 결합을 처리합니다. `교복업스`와 `교복 업스`는 같은 원문 위치로 묶되 일치한 표제어를 함께 기록합니다.
- 원문 위치·추정 원형·타입·풀이 근거·문맥 조합을 WebUI와 JSON에 제공합니다. **은어 사전 → 첨부 문맥 목록**에서 전체 200개를 검색할 수 있고, `GET /api/watchlist`에서도 조회할 수 있습니다.
- 학교급·성적 표현, 사진·영상·거래, 사진·대가·요구, 연락·영상, 술·담배 대리구매라는 다섯 종류의 조합을 표시합니다. 문장·줄바꿈·게시일·댓글 수 경계를 기준으로 가까운 단서를 대조합니다. 이는 실제 행위나 범죄 여부의 판정이 아닙니다.
- 일반어·정체성·체형·신체 부위·숫자는 단독 위험 근거로 취급하지 않습니다. 날짜·계정·URL 속 문자열과 `서울대·학생회·발표·정지선·라인업` 등의 부분 일치를 제외합니다. `영화를 보지 못했다`는 일반 동사 용례로 처리합니다.
- **ㅇㄹ → 오랄 / 오럴 / 구강성교** 후보를 표시합니다. `오랄`은 사용자가 제시한 표기로, 출처에서 확인한 `오럴 / 구강성교` 용례와 근거를 구분합니다. `요리·아래·알림`도 비교합니다. 지정한 일상 단서가 있고 다른 의미의 단서와 충돌하지 않으면 일상 후보를 우선하며, 모델의 다른 출력을 그대로 채택하지 않습니다.
- 로컬 모델에 관련 항목만 전달합니다. 원형 미확인 항목은 모델이 임의로 풀이해도 확정하지 않습니다. 중복 원형·출처는 합치고, 기존 계정·인명 표기 마스킹을 유지했습니다.
- 새 프로덕션 의존성은 없습니다. 기존 UI·사전 CRUD·발굴 기능·DB 볼륨·포트 선택 스크립트를 보존했습니다. Docker 테스트 단계에 표 가져오기 스크립트를 포함했습니다.

풀이 근거는 항목별 대표 분류 기준으로 **용례 확인 16·일반/표면 의미 123·미확인 후보 51·원형 미확인 10개**입니다. 같은 항목 안에서도 후보마다 근거가 다를 수 있습니다. `occurrence_sources`는 검색어 용례, `candidates[].sources`는 특정 풀이의 자료입니다.

## 4. 검증 결과

- 최종 Docker 테스트 이미지에서 외부 소스 마운트 없이 **pytest 64개 통과**. Starlette/httpx의 기존 사용 중단 예고 경고 1건이 있으며 실패는 없습니다.
- Python 구문·실제 runtime import·Ruff·JavaScript 구문 검사 통과. 별도 TypeScript·Node 번들 빌드가 없는 정적 JavaScript 프로젝트입니다.
- 첨부 원본에서 독립 산출한 체크섬으로 표기·타입·상태 200개를 대조했습니다. 전체 키워드 단독 대조, 조사·연속 등록어·중복 표기·숫자·일반어·게시글 경계·잘못된 모델 풀이를 검사했습니다.
- Chromium에서 `verify-watchlist-ui.cjs`, `verify-ui.cjs`, `verify-listing-ui.cjs`, `verify-context-ui.cjs` 모두 통과. 목록 검색·200개 펼치기·문맥 표시·사전 등록/삭제·TXT 업로드·JSON 내보내기·Unicode 위치·XSS 텍스트 표시를 확인했습니다.
- 1440/1280/768/390px 화면을 검사했고 가로 넘침·브라우저 콘솔 오류가 없었습니다. 데스크톱·모바일 스크린샷도 검토했습니다.
- 실제 로컬 `qwen3.5:9b`를 호출했습니다. `ㅇㄹ 레시피`는 **요리** 후보로 표시되며, 기존 게시글의 4개 표현·4개 문맥 단서 및 인명 마스킹 검증도 통과했습니다.
- Docker runtime·test 이미지 실제 빌드, `docker compose config`, healthcheck 및 HTTP API 확인 완료. 서비스는 **healthy**, `127.0.0.1:18640 → 8000`입니다. 다른 컨테이너와 겹치지 않도록 기존 포트 선택 절차를 실행했습니다.
- 최종 diff를 검토했습니다. 기존 HTML 레이아웃·실행 설정·데이터베이스 스키마·의존성 파일은 변경하지 않았습니다.

## 5. 미검증 항목과 한계

원형 미확인 10개는 **계단라·보지노·달바·야단라·게단라·달보이스·ㅁㅋ·ㅈㄷ·ㅁㅁ·야상극**입니다. 추가 문맥이나 신뢰할 수 있는 풀이 자료가 필요합니다. 미확인 후보 51개도 독립 검증된 정답이 아닙니다. 목록 일치를 보여주는 것과 정확한 뜻을 알아내는 것은 구분합니다.

새로 생기는 은어·모든 철자 변형·게시물별 의도를 전부 해석한다고 보장하지 않습니다. 규칙은 가까운 같은 문장 단서를 사용하므로 줄을 나눈 대화의 장거리 맥락을 모두 연결하지 않습니다. 로컬 모델은 최대 6,000자·48개 후보를 비교하며 오류·시간 초과 시 빠른 결과를 유지합니다. 별도 라벨 평가셋에 대한 정확도·재현율, 장시간 부하, 실제 Windows 배율별 수동 접근성 검사는 수행하지 않았습니다.

실제 사람의 나이·성적 지향·동의 여부·게시물의 불법성은 확인하지 않습니다. 사용자의 실제 분석 원문·DB·로그·모델 가중치·설정 파일은 업데이트 ZIP에 넣지 않습니다.

## 6. 적용 방법

현재 작업 폴더에는 적용·기동까지 완료했습니다. [WebUI](http://127.0.0.1:18640/)를 새로고침하세요.

같은 기존 프로젝트에 ZIP을 다시 적용할 때의 PowerShell 명령:

```powershell
Set-Location -LiteralPath 'D:\Sub\slang'
Expand-Archive -LiteralPath '.\artifacts\slang-watchlist-update.zip' -DestinationPath '.' -Force
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Slang.ps1
```

ZIP은 전체 프로젝트가 아닌 변경 파일 묶음입니다. 기존 프로젝트 위에 적용합니다. Docker 볼륨이나 사용자 사전을 지울 필요가 없습니다. 다른 프로그램이 18640을 점유하면 시작 스크립트가 사용 가능한 후속 포트를 선택하므로 출력의 `Ready` 주소를 확인하세요.
