# OCR 초성 표식 누락 수정

작성일: 2026-10-29. 현재 프로젝트에 적용하는 변경 파일 패키지입니다.

## 1. 원인

사용자가 OCR 글자는 정확하다고 확인했습니다. 같은 글자를 텍스트 분석 API에 직접 넣어도 `ㅇㄹㄴ`, `오줌ㄱㄲ`, `사탕ㅈㅇ` 모두 표식 대상이 비어 있는 현상을 재현했습니다.

`ㅇㄹㄴ`, `ㄱㄲ`는 기존 문맥 참고 자료에만 있고 확인된 원형 후보가 없어서 빠른 분석 결과에 들어가지 않았습니다. `ㅈㅇ`은 등록되어 있지만 완성형 한글에 붙은 초성을 기존 단어 경계 조건이 제외했습니다. OCR은 이 분석 결과를 원래 단어 좌표와 연결하므로 글자를 정확히 읽어도 표식이 만들어지지 않았습니다.

## 2. 수정 내용

| 입력 | 표시하는 부분 | 결과 |
|---|---|---|
| `ㅇㄹㄴ` | `ㅇㄹㄴ` | 원형 미확인 · 초성 검토 후보 |
| `오줌ㄱㄲ` | `ㄱㄲ` | 원형 미확인 · 초성 검토 후보 |
| `사탕ㅈㅇ` | `ㅈㅇ` | 자위·자위 영상·자지·지원·주의·지인 등 기존 자료의 비교 후보 |

빨간 상자는 기존 방식대로 해당 부분이 포함된 OCR 단어 전체에 표시합니다. 알려지지 않은 초성을 성적 의미로 확정하지 않습니다. 참고 자료에 원형이 없는 항목은 문맥 모델이 풀이를 만들어도 결과에 채우지 않습니다.

완성형 한글과 초성의 경계를 대조하고, 같은 줄에서 `ㅇ ㄹ ㄴ`, `ㄱ ㄲ`, `ㅈ ㅇ`처럼 띄어진 경우도 원래 상자와 연결합니다. 긴 초성 후보를 짧은 초성 접두어보다 먼저 처리해 `ㅇ ㄹ ㄴ`을 `ㅇ ㄹ`로 잘못 해석하지 않습니다. 긴 초성열 내부의 부분 문자열과 계정·URL·메일은 제외합니다. 지정된 채용·이력서/주의·안전수칙 단서에서 `ㅈㅇ`의 일상 풀이를 유지합니다. 풀이 목록은 중복을 제거합니다.

사전·첨부 목록 수는 유지하며 첨부 목록 버전은 `2026-10-29.2`입니다. OCR 인식 모델·추론 설정·화면 배치·기존 늘임 복원 기능은 유지합니다. 프로덕션 의존성을 추가하지 않았습니다.

## 3. 변경 파일

- `app/initial_candidates.py`: 공통 초성 키·경계 처리.
- `app/engine.py`: 붙은/띄어진 초성, 원형 미확인 후보, 원문 위치·풀이 후보.
- `app/watchlist.py`: 혼합 한글 초성 경계와 긴 후보 우선 처리.
- `app/contextual.py`: 미확인 원형 추측 차단, 일반 문맥 및 계정 제외 유지.
- `app/ocr.py`: 미확인 초성 표식의 표시 이름.
- `app/static/app.js`: 텍스트 화면의 미확인 초성 후보 배지.
- `app/data/context_watchlist.json`: 기존 `ㅈㅇ`의 일상 문맥 규칙.
- `tests/test_ocr_initials.py`: 새 회귀 검사 24개.
- `scripts/verify-ocr-initials-ui.cjs`: 실제 서비스 브라우저 검사.
- `README.md`, 이 보고서, `OCR_INITIALS_FILES.txt`: 사용법·변경 목록.

ZIP에는 위 12개 파일만 저장합니다. 이미지·사용자 데이터·DB·로그·캐시·모델 파일은 포함하지 않습니다. 이 프로젝트에 이미 적용된 늘임 복원 모듈을 전제로 하므로 이전 버전 전체 설치용 패키지는 아닙니다.

- 전체 pytest 139개 통과. 새 기능 검사 24개에 정확한 세 입력, OCR 띄어쓰기, 원래 좌표, 반복 등장·NFD·이모지 위치, 일상 문맥, 계정 제외, 모델의 미확인 원형 생성 차단 포함.
- Ruff 검사 및 포맷 검사 통과. Python 구문 컴파일, 실행 컨테이너 import, JavaScript 구문 검사 통과.
- Docker Compose 설정 검증, 실제 이미지 빌드·시작 및 healthcheck 통과. 기존 `127.0.0.1:18640` 포트와 데이터 볼륨 유지.
- 새 브라우저 검사 통과: 합성 이미지 실제 OCR 후 세 표현을 인식 텍스트로 지정하여 재분석, 빨간 상자 3개·원래 좌표·미확인 이름·다중 풀이 확인. 분리된 초성은 원래 상자 3개에 연결되고, 일상 문맥의 표식은 0개.
- 기존 텍스트 UI·늘임 복원 UI·OCR UI 검사 모두 통과. 1440/768/390 화면의 가로 넘침과 이미지/SVG 정렬 확인, 브라우저 콘솔 오류 없음. 기존 OCR 검사에는 PNG 저장·EXIF·끌어놓기·붙여넣기·수정·지우기 포함.
- 테스트 의존성의 Starlette/httpx 사용 중단 예정 경고 1개가 출력됩니다. 테스트 실패는 없습니다.

## 5. 미검증 항목

사용자가 분석한 원본 이미지 자체는 이번 검사에 제공되지 않아 그 이미지의 OCR을 다시 실행하지 않았습니다. 사용자가 정확하다고 확인한 인식 문자열과 합성 OCR 이미지의 좌표 재분석 경로를 검증했습니다. `ㅇㄹㄴ`, `ㄱㄲ`의 실제 원형은 확인되지 않았습니다. 특정 데이터셋 전체의 정탐률을 측정한 변경은 아닙니다.

## 6. 적용 방법

현재 실행 중인 서비스에는 반영 완료했습니다. 열려 있는 OCR 결과의 **OCR 글자 확인·수정 → 수정한 글자로 다시 분석**을 누르면 현재 인식 글자와 좌표로 표식을 갱신할 수 있습니다. 새 텍스트 화면의 배지는 페이지를 새로 열면 반영됩니다.

패키지를 같은 버전의 프로젝트 루트에 적용할 경우 상대경로를 유지해 덮어쓴 뒤 실행합니다.

```powershell
Set-Location 'D:\Sub\slang'
Expand-Archive -LiteralPath '.\artifacts\slang-ocr-initials-update.zip' -DestinationPath '.' -Force
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\Start-Slang.ps1'
Invoke-RestMethod 'http://127.0.0.1:18640/api/health'
```

다른 환경에서는 첫 줄을 실제 프로젝트 경로로 바꿉니다. 시작 스크립트가 기존 컨테이너의 포트를 확인합니다. 브라우저 검사는 README의 개발용 Playwright 설정 후 `node .\scripts\verify-ocr-initials-ui.cjs`로 실행합니다.
